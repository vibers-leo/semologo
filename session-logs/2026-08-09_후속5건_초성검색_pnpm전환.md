### 앞글자 우선 정렬 — 이게 없으면 기능이 무의미했다
첫 배포 후 실측하니 `ㅅㅅ` → 골드만'삭스' · 아'수스' · 키르기'스스'탄 이
삼성보다 위에 떴다. 전부 정당한 부분일치지만 사용자가 찾는 건 삼성이다.
`matchChoseong`(bool) 을 `choseongIndex`(매치 위치) 로 바꿔 랭킹을 만들었다.

```
rank 0      앞글자 매치      삼성
rank 1      이름/영문 매치
rank 1+i    중간 매치        골드만삭스
```
동순위는 기존 최신순 유지 (`Array.sort` 안정성에 의존).

**프로덕션 실측**
```

```

## B. 홈 PAGEERROR ✅ — 원인은 내 직전 수정이었다

풀케어 때 "AdSense 스크립트 자체가 던지는 것"으로 결론내고 미해결로 남겼는데,
틀렸다. 진짜 원인은 내가 넣은 미노출 슬롯 접기 코드였다.

```css
/* 이전 — 문서 흐름에서 빼려고 */
position:absolute; visibility:hidden; height:0; width:0;
```

`width:0` 이면 AdSense 가 `availableWidth=0` 으로 보고 **TagError** 를 던진다.
광고를 넣을지 판단하려면 실제 가용 너비가 필요하기 때문이다.
높이만 0 으로 접고 **너비는 그대로 두는** 것으로 해결.

실측: 홈 · 브랜드 페이지 · 요청 페이지 **PAGEERROR 0**.

## D. Firestore 규칙 ✅ — 배포 완료

규칙은 `ai-recipe` 레포에 있고 프로젝트(`ai-recipe-lab`)를 공유한다.
REST API 로 프로덕션에 직접 질의해 확인했다.

| 컬렉션 | 실측 | 문제 |
|---|---|---|
| `logo_requests_public` | ❌ PERMISSION_DENIED | **규칙 자체가 없어 deny-all** |
| `logo_quality` | ✅ 읽기 허용 | `write: if true` — 누구나 값 조작·삭제 가능 |

**`/request` 공개 요청 게시판이 프로덕션에서 완전히 죽어 있다.** 읽기·쓰기 모두
거부되는데 클라이언트가 `catch { setItems([]) }` 로 삼켜서 "요청이 없어요" 로만 보인다.

사용자 승인 후 배포했다. 1차로 프로덕션에서 직접 공격해 검증했고,
이후 **에뮬레이터 단위 테스트 18건**으로 다시 검증했다.

### JDK 는 이미 있었다

### 테스트가 잡은 진짜 버그
18건 중 1건이 실패했다 — **`down` 필드가 없는 문서에 투표하기**.
`request.resource.data.down` 처럼 직접 접근하면 그 필드가 없을 때 평가 에러가
나서 업데이트가 영구히 거부된다. 즉 **그 브랜드는 다시는 투표를 받을 수 없다.**
양쪽 다 `get(field, 0)` 으로 바꿔 해결, 재배포했다.

프로덕션 `logo_quality` 9건을 Admin SDK 로 전수 조사하니 up/down 누락 0건이라
실제 피해는 없었다. 세션로그에 "걸릴 수 있다"고 적어둔 잠재 위험이 실재했던 것.

테스트는 `ai-recipe/firestore-rules-test/` 에 남겼다 — 레포 루트의
`firestore.rules` 를 직접 읽어 사본이 갈라지지 않는다.

### 로컬 빌드가 왜 안 됐는지 — 심링크였다
`CLAUDE.md` 에 "Turbopack 이 외장SSD 심링크를 처리 못 함 → CI 에서만 빌드"라고
적혀 있었는데, 정확한 원인은 **경로가 프로젝트 밖으로 나가 있던 것**이었다.

```
node_modules → /Volumes/Untitled/macminim4-cache/.../node_modules
.next        → /Volumes/Untitled/macminim4-cache/.../.next
```
둘 다 같은 외장 볼륨이지만 프로젝트 루트를 벗어나서
`Symlink [project]/node_modules is invalid, it points out of the filesystem root` 이 났다.

프로젝트 안 실폴더로 되돌리자 **로컬 빌드 성공** (6,822 페이지, 약 3분).
`.next` 를 안 지웠을 땐 16.2.12 시절 산출물이 남아 `/sitemap.xml` 수집이
`routeModule.ensureUserland is not a function` 으로 깨졌다 — 캐시를 지워야 한다.

외장 배치는 유지된다. 스토어 `/Volumes/Untitled/dev/.pnpm-store/v11` 이
프로젝트와 **같은 볼륨**(`/dev/disk7s1`)이라 하드링크 dedup 이 실제로 작동한다.

## 추가 — CF 캐시 규칙 (JSON 엣지 캐시)

`brands-slim.json`·`brands.json` 이 `cf-cache-status: DYNAMIC` 이었다.
Cloudflare 기본 정적자산 규칙에 `.json` 이 없어서 **모든 인덱스 요청이
GitHub Pages 오리진까지 갔다.**

zone `vibers.co.kr` 의 기존 룰셋 `Static Assets Cache` 에 3번째 규칙으로 **추가**
(기존 2개는 손대지 않음):

```
조건  http.host eq "logo.vibers.co.kr" and ends_with(path, ".json")
동작  cache=true, edge_ttl=3600(override), browser_ttl=respect_origin
```

엣지 TTL 을 길게 잡아도 안전한 이유: 사이트가 `?v={VERSION}` 을 붙이고
CF 캐시키에 쿼리스트링이 포함되므로, 브랜드를 추가하면 URL 이 바뀌어 즉시 갱신된다.

검증: 세 URL 모두 MISS → HIT 확인, JSON 파싱 정상(6,825건).
`DYNAMIC` 이 섞여 보이는 건 **PoP 마다 캐시가 독립**이라 각 지점의 첫 요청이
MISS 이기 때문이다 — 오판하지 말 것.
