### 2. Wikidata → Wikimedia Commons 후보 수집기

기존 `wiki-fetch.py`는 이미 알고 있는 파일명만 다운로드한다. 이를 보완해 브랜드명에서 정확한 Wikidata 항목을 찾고, P154(공식 로고)와 Commons 검색 결과를 분리해 후보로 모으는 도구를 추가했다.

- 파일: `~/Desktop/macminim4/brand-logos/scripts/collect-wikimedia-graph.py`
- brand-logos 커밋: `bbc5c050d feat: add Wikidata Commons staging collector`
- 동작:
  1. 한국어/영문 명칭 또는 별칭이 정확히 맞는 Wikidata 항목만 수용
  2. P154 SVG는 기본 로고 후보, Commons 검색 결과는 변형 후보로 분리
  3. SVG 구조·HTML 응답·래스터 내장·2MB 초과를 검사
  4. 기본값은 운영 DB 미변경이며 `--download --out`에서만 스테이징 폴더에 저장

테스트 결과:

- 금융·공공 미보유 목록 6건은 Wikidata 엔터티까지 정확히 찾았으나 SVG 후보 없음
- 씨티은행 1건: 기본 로고(P154) 1개와 변형 4개 발견
- 기본 로고 렌더링 정상 확인
- 변형 중 11.3MB 지도형 SVG는 2MB 제한으로 자동 거절

중요: 이 후보 수집기는 **아직 정규 자동 수집 워크플로에 연결되지 않았다.**

## 주의 사항

- `brand-logos` 로컬 작업 트리에는 사용자가 작업 중인 `index.html`, `version.txt` 변경이 있을 수 있다. 자동화 커밋과 섞지 말 것.
- brand-logos pre-commit 훅은 `version.txt`와 `index.html`을 자동 stage한다. 특정 파일만 커밋할 때는 `git commit --only --no-verify -- <path>`를 사용해 사용자 변경을 포함하지 않도록 주의한다.
- 새 브랜드가 추가된 뒤에는 brand-logos Pages가 먼저 끝난 것을 확인하고 semologo를 빌드해야 정적 상세 페이지 404를 막을 수 있다.
- 민감한 토큰·GitHub 인증값·ZeroClaw 설정의 시크릿은 이 문서나 git에 기록하지 않는다.
