# 세모로고 로고 심볼 복원 + CDN 캐시 오염 사고 (2026-08-14)

## 무엇을 했나

사용자가 "컨텐츠의 세모로고는 삼각김밥 베어문 심볼이 빠진거같아" 라고 지적했다.
등록해둔 `logo.svg` 가 워드마크만 담고 있었다.

1. **심볼 복원** — 원본에서 삼각 실루엣을 트레이싱(그림자 제외 y≤254, 8배 업스케일,
   3D 하이라이트 줄무늬는 flood fill 로 제거)하고, 원본의 정확한 배치를
   잉크 바운딩박스로 측정해 심볼+워드마크로 합성했다.
   - 심볼 282×254 @ (1,1) / 워드마크 660×219 @ (322,40) / 캔버스 983×265
2. **변형 라벨 정정** — 매니페스트가 옛 상태(워드마크형)로 남아 브랜드 페이지에
   잘못 표시됐다. 재생성하니 심볼형은 잡혔지만 `logo.svg` 는 여전히 워드마크형.
3. **심볼 PNG 512 추가** — 심볼 카드에 SVG 만 있었다.

## 배운 것 3가지

### 1. 자동 분류는 종횡비만 본다
`logo.svg` 는 983×265 = **종횡비 3.7** 이라 워드마크 기준을 넘는다. 실제로는
심볼+워드마크 로크업인데 분류기가 알 방법이 없다. 손으로 바로잡고
`variants.override.json` 으로 고정했다 — 다음 자동 재생성이 덮어쓰지 않는다.

### 2. ⚠️ 배포 대기 중 폴링이 캐시를 오염시킨다 (이번 최대 삽질)

새 VERSION URL 로 CDN 반영을 확인하려고 10회 폴링했다. **그 폴링이 배포 전
응답을 그 URL 에 캐시로 박아버려서**, 배포가 끝난 뒤에도 사이트가 옛 매니페스트를
받았다. 오리진과 새 URL(무작위 파라미터)은 내내 정상이었다.

- CF 캐시 규칙의 **엣지 TTL(1시간)이 오리진 `max-age=600` 을 덮어쓴다**
  → `age=1046` 인데도 `cf-cache-status: HIT`
- 퍼지는 현재 토큰 권한으로 안 된다 (`10000 Authentication error`).
  `CLOUDFLARE_VIBERS_TOKEN` 은 zone 조회만 되고 purge 는 막혀 있다
- 해결: **VERSION 을 새 값으로 올려 오염 안 된 URL 로 우회**. 즉시 해결된다

```bash
❌ curl ".../variants.json?v=$NEW_VERSION"   # 확인 행위가 그 URL 을 옛 값으로 고정
✅ curl ".../variants.json?probe=$RANDOM"
```

`brand-logos/LOGO_PROMPT.md` 5번 단계에 남겼다.

### 3. cairosvg 는 실패해도 조용히 빈 이미지를 뱉는다
심볼 PNG 를 만들고 **잉크 비율(62.5%)로 검증**했다. 파일이 생겼다는 것만으로는
렌더 성공을 알 수 없다.

## 중간에 저지른 실수 (둘 다 렌더해봐서 잡음)
- viewBox 를 그대로 쓰니 심볼이 세로로 늘어났다
- 크롭 좌표가 음수라 PIL 이 검정으로 패딩 → flood fill 이 막혀 심볼이 검은 사각형이 됐다

**눈으로 렌더해보지 않았으면 둘 다 그대로 배포됐다.**
