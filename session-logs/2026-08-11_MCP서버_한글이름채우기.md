# 세모로고 — MCP 서버 + 한글 이름 데이터 수리

## 발단
"API 키를 주면 CLI 로 로고를 쓸 수 있는 것 아니냐"는 질문에서 시작했다.
확인해 보니 **키가 막고 있던 게 아니었다** — CDN 이 이미 공개라 오늘 당장
`curl` 로 받아진다(실측 HTTP 200, 2,305 bytes). 키의 역할은 여는 게 아니라
재는 것이다. 그래서 키 대신 **쓰기 편한 통로**를 먼저 만들기로 했다.

## A. MCP 서버 (`mcp/`)

`npx semologo-mcp` — Claude Code·Cursor 에서 대화 중에 로고를 가져온다.

```
"헤더에 스타벅스랑 카카오 로고 넣어줘"
  → search_brands → get_logo → SVG 원문이 코드에 바로 들어감
```

**서버를 두지 않는다.** 사용자 기기에서 돌며 공개 CDN 을 읽을 뿐이라
운영비도 인증도 사용량 제한도 없다.

도구 3개: `search_brands` · `get_logo`(SVG 원문) · `get_logo_url`

챙긴 것:
- **정확 일치 최우선 정렬** — 없으면 "samsung" 에 samsung-pay 가 본체보다
  위로 와서 에이전트가 엉뚱한 로고를 코드에 박는다
- **GitHub Pages 404 함정 차단** — 404 가 200+HTML 로 오므로 `<svg` 확인.
  안 막으면 "SVG 인데 열리지 않는 파일"이 코드에 들어간다

검증: stdio JSON-RPC 로 실제 핸드셰이크 + 6종 실동작.

## B. 한글 이름 — 이게 더 큰 문제였다

MCP 를 만들다 데이터를 재보고 발견했다.

```
노출 브랜드                6,381
name_ko 에 한글 없음       5,340  (84%)
name_ko == name_en         6,275
```

`samsung` 의 name_ko 가 **"samsung"**, `naver` 는 "Naver" 였다. 결과:

> **"삼성"으로 검색하면 삼성화재·삼성증권은 나오는데 삼성 본체가 안 나왔다.**

전날 넣은 초성 검색도 한글이 있어야 동작하므로 **대표 브랜드에서 통째로
무력**했다. "한국 브랜드 + 한글 검색"을 해자라고 불렀는데 정작 최대어들이
그 밖에 있었다. SEO 도 마찬가지 — 사람들은 "삼성 로고"라고 검색한다.

### 두 축으로 나눴다
| 필드 | 용도 |
|---|---|
| `name_ko` | 화면에 보이는 정식 이름 (삼성·네이버·카카오·쿠팡·포스코…) |
| `aliases` | 검색 전용. LG·SK·KT 는 로마자가 정식이라 이름을 '엘지'로 바꾸면 안 되지만, '엘지 로고'로 찾는 사람은 실재한다 |

34건 적용. `scripts/fill-korean-names.py` 로 재현 가능하게 남겼다.
`aliases` 는 build-slim → 사이트 검색 → MCP 검색 세 곳에 연결했다.

### 이름만 보고 넣다가 2건을 잡았다
- `starship` → 스타쉽엔터테인먼트가 **아니라** Rust 셸 프롬프트 (`starship.rs`)
- `compose`  → 컴포즈커피가 **아니라** Docker Compose

**한글명을 넣기 전 `category`·`domain` 확인은 필수다.** 적용 직전에 확인해서
틀린 이름이 배포되는 걸 막았다.

## C. 검색 순위 — 두 번 고쳤다
1. 초성일 때만 순위를 매기고 일반 입력은 필터만 걸어서, 브랜드 이름을 정확히
   쳐도 본체가 상위에 안 나왔다 → 두 경로를 합치고 정확일치를 최상단으로
2. 앞글자 매치가 전부 동점이라 "ㅅㅅ" 에 삼성중공업이 삼성보다 먼저 나왔다
   → 짧은 이름 우선 보정 (MCP 와 같은 규칙)

## 검증 (프로덕션)
```
"ㅅㅅ"   → 삼성 · 삼성물산 · 삼성화재
"삼성"   → 삼성 · 삼성물산 · 삼성화재
"ㅋㅋㅇ"  → 카카오 · 카카오M · 카카오뱅크
"엘지"   → LG        "카이스트" → KAIST
브랜드 페이지 <title> = "삼성 로고 SVG·PNG 무료 다운로드 | 세모로고"
PAGEERROR 0
```

## 함정 기록
- **배포 모니터링 오판** — `gh run list --limit 1` 은 *이전* 런의 성공을 볼 수
  있다. 커밋 SHA 로 특정해야 한다 (`select(.headSha==...)`)
- **엣지 전파 지연** — 배포 직후 테스트는 옛 번들을 읽을 수 있다. 한 번
  "안 고쳐졌다"고 오판했다가 재확인해서 정정했다
- **셸 명령 치환은 NUL 을 삼킨다** — `$(... | wc -c)` 로 NUL 을 세면 0 이 나온다.
  BrandGrid.tsx 에 NUL 2개가 커밋돼 있었는데 이 때문에 "없다"고 오판했다
  (파이썬 바이트 카운트로 재서 잡음)

### ② 미보유 24건 (기록만, 수집 실패)
`_clients/collect-wanted.json` 에 도메인·카테고리와 함께 기록했다.

처음엔 "24건 모두 WVL 에 없음"으로 결론냈는데, 대조군을 돌려보고 **내 탐침이

### ③ 도메인 기반 수집 — 24건 시도, 4건 확보

WVL 경로가 죽어 있어 공식 홈페이지에서 직접 긁는 방식으로 갔다.
정적 HTML 을 curl 로 받아 `logo|symbol|ci|bi` 패턴의 svg/png 를 후보로 뽑는다.

**두 번 걸러야 했다.**

1차(느슨한 규칙)에서 "SVG 5건 확보"가 나왔는데 **4건이 로고가 아니었다**:
```
한국전력공사     search_20x20.svg  752B   ← 돋보기 아이콘
식품의약품안전처   bx-news.svg       554B   ← 뉴스 불릿
국민연금        bg_desc_w.svg     771B   ← 배경 장식
전북은행        aa+.svg           635B   ← 플러스 아이콘
```
→ 파일명에 `icon|arrow|search|bg_|\d+x\d+` 가 있으면 배제, SVG 최소 1.5KB 로 조정.

2차(엄격) 후에도 **PNG 후보의 절반이 로고가 아니었다.** 전부 렌더해 대조 시트를
만들어 눈으로 확인하고서야 걸러졌다:
```
kepco  logo_wa.png             → 'WA 웹접근성 품질인증' 마크 (wa = Web Accessibility)
fsec   logo-main-partner06.png → '마이데이터 테스트베드' 파트너 로고
travel-wallet · bizplay        → 빈 이미지
```

**교훈: 로고 수집은 파일명·크기로 1차 필터링하고, 저장 전에 반드시 렌더해서
사람이 확인한다.** 안 그러면 한국전력 로고 자리에 웹접근성 인증 마크가 박힌다.

확보 4건 — `korea-gas-safety`(SVG) · `mfds` · `ssg-payments` · `kona-i`.
뒤 둘은 **요청한 브랜드와 다르다.** 받은 로고가 'SSG PAYMENTS'(신세계 계열 PG)와
'KONA I'(회사)라서 실체대로 등록했다. SSG페이·코나카드 자체는 여전히 미수집이고,
`코나카드`로 검색하면 `코나아이`가 나오도록 별칭을 걸었다.

수확이 낮은 이유: 한국 기업 사이트는 로고가 CSS 스프라이트에 있거나 JS 렌더라
정적 HTML 파싱으로 안 잡힌다. 16건은 후보 자체가 없었다.

### ④ 덤 — 가짜 SVG 9건 (자동수집 잔재)

## E. 수집기 저장 가드 + headless 수집

### ① `scripts/assetguard.py` — 같은 사고를 구조적으로 막는다

404 HTML 이 `logo.svg` 로 저장되는 사고가 반복됐다(오늘 9건, 이전 519건).
수집기마다 검사가 제각각이라 빠지는 곳이 생겼으므로 **공통 가드**를 뒀다.

- 매직바이트로 실제 형식 판별 — 확장자를 믿지 않는다
- HTML·빈 응답·확장자 불일치·과소 용량이면 **쓰지 않고** `False`
- 자체 점검 6건 내장 (`python3 scripts/assetguard.py`)

수집기 9개 전부 연결: collect-auto/global/logodev · wiki-fetch ·
import-gilbarbara/worldvectorlogo/government-logos · recollect-logos ·
upgrade-png-to-svg. 실패 시 등록도 건너뛰도록 호출부를 함께 고쳤다.

**⚠️ 일괄 치환이 버그 7곳을 만들었다.** 정규식이 괄호로 감싼 경로를 잘못 집어
```python
(dest / "logo.svg").write_bytes(raw)   →   (safe_write(dest / "logo.svg"), raw)
```
로 바꿔놨다. 인자 하나짜리 호출 + 튜플이라 **`py_compile` 은 통과하는데 실행하면
죽는다.** 컴파일만 확인하고 넘어갔으면 다음 수집이 통째로 실패했을 것이다.
모듈을 실제로 import 해서 잡았다.

> 자동 치환 후에는 컴파일이 아니라 **실행(import)까지** 확인한다.

### ② headless 수집 — 20건 시도, 4건 확보

정적 파싱이 실패한 이유는 로고가 CSS 스프라이트·JS 렌더·인라인 SVG 에 있어서다.
**파일명이 아니라 위치와 역할**로 찾도록 바꿨다 — 헤더 좌상단(top<220, left<700)의
img·인라인 svg·CSS background.

20건 중 10건에서 후보가 나왔고, 렌더해 눈으로 확인해 4건만 남겼다:
`sk-planet` · `travel-wallet` · `incheon-airport` · `eland-retail`

버린 것들: 한패스·비즈플레이(빈 이미지) · 국민연금('국민이 주인인 연금' 슬로건) ·
인천공항 3건(텍스트·비행기 아이콘·알림 아이콘) · 금융보안원(심볼만 있는데
'마이데이터 테스트베드' 로고와 같은 심볼이라 확신 불가 → 보류).

접속 실패 4건은 원인이 다르다 — BNK부산은행·한국전력 타임아웃,
한국투자증권·라이나생명 **인증서 CN 불일치**(등록 도메인이 실제 서비스와 다름).
collect-wanted.json 의 도메인을 고쳐야 한다.

**중간에 파일명 충돌 사고가 있었다.** 슬러그 함수가 한글을 전부 제거해
7개 브랜드가 `x-0.png` 하나에 덮어써졌다(크기가 전부 같아서 발견). 브랜드
인덱스 기반 파일명으로 바꿔 해결.
