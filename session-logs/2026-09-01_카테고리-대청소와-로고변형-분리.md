# 카테고리 대청소와 CI 시트 로고 변형 분리

## 무엇을 했나

### 1. CI 매뉴얼 시트에서 로고 변형 떼어내기

한 이미지에 여러 버전이 들어 있던 지자체 로고를 각각 분리했다.

| 브랜드 | 원본 | 결과 |
|---|---|---|
| 군포시 | 1200x1667 CI 매뉴얼 페이지 | 조합형(대표)·기본형·태그라인 **3변형** |
| 예천군 | 심볼 + 인장 여러 종 | 상단 대표 심볼 338x238 |
| 원주시 | 설명문 7줄 + 로고 | 로고만 577x292 |

**핵심은 유채색만 보는 것.** 잉크량만 보면 군포는 회색 헤더바가 75,964로
실제 로고(20,811)보다 많아 헤더를 로고로 착각한다. 로고는 브랜드 컬러,
헤더·설명문·치수선은 무채색이다.

무채색 로고에는 쓸 수 없어 자동 적용하지 않는다. 지자체 191개 스캔에
후보는 2건뿐이었다.

`collect_krx_lib.split_first_block` 도 '위쪽 제목 떼기'에서
'잉크 최다 덩어리 선택'으로 바꿨다. 중간에 낀 설명문을 못 걸렀다.
최다 덩어리가 전체 잉크의 40%를 넘을 때만 적용해 과절단을 막는다.

### 2. 기타 8,371 → 5,888

이름 규칙으로는 4%(371건)밖에 못 잡았다. `Melitta`·`Tefal` 같은 이름에는
업종 신호가 아예 없다. 그런데 8,090개에 위키데이터 QID가 있었다.

세 겹으로 본다:
- **P452(업종)** — 가장 구체적. 먼저 본다
- **P31(분류)** — `business`·`public company` 같은 법인격은 일부러 뺐다.
  3,500건이 몰려 있어도 업종이 아니라 형태라 신호가 아니다
- **설명문** — `German coffee company` 처럼 업종이 문장에 들어 있다. 1,108건

### 3. 카테고리 오분류 862건 교정

| 발단 | 드러난 것 |
|---|---|
| BTS가 암호화폐에 | 티커 이름 충돌. 유니티(게임 엔진)도 같은 자리에 → 2건 |

인천국제공항공사가 공공기관에 있었다.

### 4. 숨김 65건

- 로고 파일 없음 49건
- 빈 이미지 16건

숨기되 지우지 않는다 — 목록·사이트맵·프리렌더에서 빠지고 상세 페이지는
`noindex`로 살려 둔다. 이미 색인된 URL을 404로 만들면 SEO만 잃는다.

## 실패에서 배운 것

### 자동 판정을 세 번 틀렸다

**빈 로고 판정** — 잉크 비율로 재니 177건이 걸렸는데 스냅챗·소니·유니티·
아스날이 들어 있었다(밝은 색 로고). 알파로 바꾸니 이번엔 흰색 로고가
걸렸다. 결국 *모양*으로 갈랐다: 흰 로고는 불투명 픽셀이 글자 모양이라
비율이 낮고, 흰 사각형은 화면 전체가 불투명하다. 16건으로 좁힌 뒤
흰/검은 배경 양쪽에 그려 눈으로 확인했다.

**통짜배너 1,048건·문장이미지 594건은 자동 처리하지 않았다.** 국기가
잉크 100%라 전부 걸리고 배민·컬리·덴티움 같은 정상 로고가 대부분이었다.

**QID 추측** — 존재하지 않는 `Q4830453f` 를 매핑에 넣어 Avon(화장품)이
공공기관이 됐다. 지금 매핑은 전부 실제 레이블을 조회해 확인한 것이다.

### 정규식 함정 3개

```python
r"financial technolog)\b"   # ❌ technolog 뒤에 y 가 와서 경계가 아니다 → 조용히 미매칭
r"(?i)\b(nasa|...)"          # ❌ (?i) 가 중간에 있으면 PatternError
r"\b(bank|...)"              # ❌ 'voice banks' 가 금융으로 → (?<!voice ) 필요
```

첫 번째가 특히 위험했다. 에러 없이 그냥 매칭이 안 된다.

### 구체 → 포괄 이동은 막아야 한다

현대자동차그룹이 `자동차`→`제조·그룹`, 코에이·에닉스가 `게임`→`미디어·엔터`로
가는 건 설명문상 맞지만 사용자가 찾기는 더 어려워진다.

### 옮기지 않은 것도 이유와 함께 코드에 박는다

```

Monsters University   디즈니 영화

```

## 인프라 수정

### rebase-push.sh — rebase 실패를 삼키고 있었다

증상은 `non-fast-forward` 세 번뿐이라 원인이 안 보였다. 실제로는
unstaged(`__pycache__`) 때문에 rebase가 **시작조차 못 했고** `|| true` 가
그 실패를 삼켰다.

더 나쁜 것: 병합 스크립트가 인자 없이 호출돼 사용법만 출력했는데
`git add -A` 가 **충돌마커째 스테이징**해 깨진 brands.json이 커밋됐다.

가드 3개를 넣었다 — unstaged 검사 / 충돌마커 검사 / JSON 유효성 검사.

### 스캔이 CPU 루프에 갇혔다

렌더가 오래 걸리는 건 파일 크기가 아니라 path 복잡도다. 1.5MB 상한을
걸었는데도 같은 자리에서 또 40분을 갇혔다. `signal.alarm(8)` 로 시간을
끊는 게 유일한 답이었다.

### 배포 확인

`deploy.status` 가 `SUCCESS` 인데 **직전 배포의 상태값**이었다.
컨테이너 생성 시각을 함께 봐야 진짜 새 배포인지 알 수 있다.

## 2부 — 중복 로고로 '잘못 올라간 것' 찾기

판정기(잉크·알파·문장)는 오탐이 지배적이었다. 국기는 잉크 100%라 전부
'통짜배너'로 걸리고 한글 워드마크는 전부 '문장이미지'로 걸린다.

**두 브랜드가 바이트까지 같은 이미지를 쓰면 하나는 반드시 틀렸다.**
판정이 아니라 사실이다. 중복 그룹 160개 · 브랜드 393개.

### 숨김 85건 추가 (누계 150)

| 부류 | 건수 | 내용 |
|---|---|---|
| 이니셜 폴백 | 64 | 로고 대신 첫 글자 아이콘. 서울주택도시공사·SR·세브란스병원이 전부 같은 'S' |
| 가비아 로고 | 7 | 홈페이지 **푸터의 호스팅 업체 로고**를 가져왔다 |
| GOODZZ 로고 | 8 | Vibers 프로젝트에 다른 브랜드 로고가 적용 |
| 기타 | 6 | koreabasketball에 문화체육관광부 · kgmobility에 KANEMATS |

정상은 남겼다 — LG그룹·K리그·k8s·KCC·금호·태광은 계열사가 같은 로고를
쓰는 게 맞다. 시트로 눈검사해 5건을 되살렸다.

재발 방지로 수집기에 **벤더 로고 차단** 추가(가비아·카페24·아임웹·powered-by).

### 중복 등록 84건 흡수

`cgv`/`cj-cgv` · `ahnlab`/`ahnlab-inc` · `socket_io`/`socket.io` …
지우지 않고 `variant_of` 로 부모에 흡수 — canonical이 부모를 가리켜
색인된 URL을 잃지 않는다.

**부모는 검색될 id 여야 한다.** '한글명 있는 쪽'을 부모로 했다가
`korail`→`kr-korail`, `cgv`→`cj-cgv` 로 사람이 검색하는 짧은 id가
자식이 됐다. 기준을 바꿨다: 수집 흔적(logo-*·kr-*)·접미사·연속 하이픈이
없는 쪽 → 짧은 쪽. 부모에 없는 정보는 자식에서 채웠다(38필드 + 한글명 12건).

⚠️ 한글 우선이 항상 옳지 않다. `EBS`→`EBS영어`, `CJ ENM`→`CJ엔터테인먼트`는
   오히려 나빠져 되돌렸다.

흡수하지 않은 39건 — 롯데온/롯데마트, 카카오페이지/카카오웹툰처럼
계열사가 그룹 로고를 공유하는 경우다. (도메인만으로 판정했다가
dall-e와 sora가 묶일 뻔했다 — openai.com)

## 3부 — 사이트가 60개에서 멈춘 사고

원인 세 겹이 겹쳐 있었다.

### ① 캐시 규칙에서 홈을 빠뜨렸다

8월 30일에 `/brand/:id*` 만 고치고 홈을 놓쳐 Next 기본값
`stale-while-revalidate=1년` 이 그대로였다. CF에 박힌 옛 HTML이 가리키는
JS 청크가 새 배포에서 사라져 **ChunkLoadError**. 서버 렌더분 60개에서 멈췄다.

```
정적 자산 뺀 전 경로 → max-age=60 · s-maxage=600 · stale 600
```
**HTML의 stale은 배포 주기보다 길면 안 된다** — 청크 파일명이 매번 바뀐다.
`_next/static` 은 파일명에 해시가 있어 immutable이어도 안전하므로 제외.

캐시 헤더는 **이미 열린 탭을 못 구한다.** `ChunkRecovery` 를 추가해
ChunkLoadError를 잡아 한 번만 새로고침한다(sessionStorage로 무한 루프 방지).

### ② rebase가 slim을 원격 것으로 덮었다

`brands.json` 은 잘 병합됐는데 파생물 `brands-slim.json` 이
'재생성물은 원격 것' 규칙에 걸렸다. 크론이 만든 slim은 교정 **이전**
기준이라 목록·검색이 며칠 된 값을 보여줬다. 병합 직후 재생성하도록 수정.

### ③ CF 퍼지 — 글로벌 키로 가능했다

개별 토큰 4개가 전부 인증 오류였는데 `CLOUDFLARE_GLOBAL_API_KEY` +
`X-Auth-Email`/`X-Auth-Key` 헤더로 성공했다. 이전에 "권한 없음"으로
판단해 사용자에게 수동 퍼지를 부탁한 것은 이 키를 안 써봤기 때문이다.

```bash
curl -X POST "https://api.cloudflare.com/client/v4/zones/{zone}/purge_cache" \
  -H "X-Auth-Email: $CLOUDFLARE_ACCOUNT_EMAIL" \
  -H "X-Auth-Key: $CLOUDFLARE_GLOBAL_API_KEY" \
  --data '{"purge_everything":true}'
```

## 4부 — 저장소 크기

**50MB 경고는 오해였다.** push에서 본 'brands.json 52.49MB'는 rebase 병합이
실패해 **충돌마커가 든 깨진 파일**이었다. 실제로는 21.8MB.

진짜 원인은 **pack 파일 47개 조각화**였다. pack 사이에서는 델타를 못 잡는다.
`git gc --aggressive` 로 하나로 합쳐 **1.7GB → 1.3GB**.

한 줄 JSON이 원인일 거라 의심해 줄바꿈 포맷과 델타 효율을 실측했는데
2.8MB로 동일했다 — 원인이 아니었다.

큰 SVG 8건을 svgo로 줄였다(american-legion 10.3→7.1MB, evil-dead-rise 7.2→2.7MB).
⚠️ **svgo 결과를 그대로 믿으면 안 된다.** 전후를 300px로 렌더해 픽셀
평균차 1.5 미만일 때만 교체한다. `speed` 브랜드가 40.29로 나와 원본을
유지했다 — 검증이 없었으면 깨진 SVG를 배포했다.

두 함정: `os.replace` 는 볼륨을 넘지 못한다(외장 SSD ↔ 시스템 /tmp).
svgo는 path가 복잡하면 몇 분씩 걸린다(120초로 끊음).

**남긴 것:** `sources/raster-wrapped/` 303MB·1,050개. gitignore로는 앞으로만
안 쌓이고 이미 쌓인 이력은 안 줄어든다. `git rm --cached` 는 2026-08-18에
로컬 PNG 40,994개가 사라진 경로다. 이득 대비 위험이 커서 두기로 했다.
