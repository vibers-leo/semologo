# 수집 크론 4연속 실패 — 진단과 복구

크론이 4회 연속 실패하고 3~4시간씩 돌다 죽고 있었다. 원인이 셋이었다.

## ① Illustrator SVG 435건이 렌더 실패

cairosvg 는 defusedxml 로 파싱하는데 그게 **모든** 엔티티 선언을 거부한다
(EntitiesForbidden). 그런데 Adobe Illustrator 가 내보낸 SVG 는 거의 항상
이렇게 생겼다:

```xml
<!DOCTYPE svg [ <!ENTITY ns_svg "http://www.w3.org/2000/svg"> ]>
<svg xmlns="&ns_svg;">
```

실제 위험(XXE)이 아니라 네임스페이스 별칭인데 파생물을 통째로 못 만들었다.

`unsafe=True` 로 푸는 건 답이 아니다 — 외부 엔티티까지 열려 신뢰할 수 없는
SVG(위키미디어·웹 수집분)에 XXE 를 허용하게 된다.
**내부 선언만 값으로 치환하고 DOCTYPE 을 지운다.**

### 엔티티 다음으로 흔한 것 — SVG 자체의 오작성

315건이 살아난 뒤에도 120건이 남았고, 패턴이 뚜렷했다:

| 오작성 | 원인 |
|---|---|
| `stroke-opacity="null"` `opacity="undefined"` | JS 로 만든 SVG |
| `letter-spacing="-0.2r"` | rem 단위를 잘라먹음 |
| `fill="rgb(65 74 71)"` | CSS Color 4 공백 구분 — cairosvg 미지원 |
| `xmlns` 누락 | unbound prefix 로 죽는다 |

`sanitize()` 로 넷을 고쳐 **91건이 더 복구**(120 → 29).
남은 29건은 시간 초과 13 · 크기 초과 6 · 진짜 깨진 것 10.

**총 435건 중 406건 복구.** 렌더 결과는 시트로 눈검사했다.

## 지자체 — 수집기가 `<img>` 를 아예 안 봤다

미수집 66곳을 추적하니 수집기가 **href 만 훑고** 페이지에 박힌 로고
이미지를 통째로 놓치고 있었다. 구리시 휘장은 `cts416_img.png` 라
파일명에 logo·symbol 이 없고 다운로드 링크도 없다.
그런데 alt 는 "시 휘장 이미지" 로 정확하다 —
**한국 지자체는 웹접근성 의무로 alt 를 성실히 단다. 파일명보다 믿을 만하다.**

alt 기반 수집으로 12곳에서 이미지를 새로 찾았다.

⚠️ alt 에 상징어가 있어도 실물이 사진인 경우가 있다(`시목 소나무` = 나무 사진).
   KOGL·공공누리·태극기와 함께 NOISE_ALT 로 뺐다.

## 오늘 두 번 반복한 실수

**버킷 동기화 스크립트가 둘로 갈려 있다:**


sync-all 만 돌리고 "업로드 452개 완료"를 보고 끝난 줄 알았는데, 방금 복구한

`hidden` 을 빠뜨렸다. 거르는 조건이 두 곳으로 갈리면 반드시 어긋난다.
