# 조건부 운영서버 빌드 (2026-10-14)

세모로고의 `.prebuilt-only` 표시를 해제하고 공용 배포 대기열을 통한 서버 빌드를 다시 허용했다. `git push` 웹훅은 `/root/scripts/vibers-managed-deploy.sh`를 거쳐야 하며, 앱별 잠금과 전역 잠금은 유지한다. 이 디렉터리의 두 스크립트는 적용 시점의 서버 버전 사본이다.

빌드 시작 조건은 3회 연속 충족해야 한다. BuildKit 메모리 4GiB, 추가 스왑 0, CPU 1.5개 상한을 확인하고, `MemAvailable >= 5GiB`, 메모리 PSI avg10 `some < 1%`·`full < 0.1%`, 실제 스왑 입출력 `<= 128 pages/s`, 디스크 I/O PSI avg10 `some < 5%`·`full < 1%`를 요구한다. 조건이 맞지 않으면 최대 약 12분 대기한 뒤 실패한다. 빌더는 실행 종료 시 정지된다. **I/O 검사는 시작 전 대기 조건이며 실행 중 I/O 대역폭 제한은 아니다.**

실제 시험 배포에서 로컬 기준 홈페이지 응답은 빌드 전 0.32~0.51초, 빌드 중 대체로 0.28~0.47초였고 모두 HTTP 200이었다. `next build`와 이미지 내보내기 중 디스크 I/O PSI `full`이 약 5~9%까지 올라갔으므로, 다른 서비스의 응답 문제가 발견되면 서버 빌드를 다시 중단하고 외부 사전 빌드 이미지로 배포한다. 빌드 완료 후 `check-deploy.sh`는 `DEPLOY OK`, 컨테이너는 healthy/restarts 0, 빌더는 exited를 확인했다. 미추홀구 검색 결과에서 대표 콘텐츠 이름과 마스코트 정렬도 확인했다.

서버 롤백 자료는 `/root/ops/deploy-policy-20261014/`에 있다. 정책을 되돌릴 때는 전역 배포 잠금을 잡은 상태에서 그곳의 이전 스크립트를 `/root/scripts/`로 복원하고 빌더 CPU quota를 이전 값인 `200000/100000`으로 되돌린다. 세모로고만 서버 빌드를 즉시 중단할 때는 `/root/projects/semologo/.prebuilt-only`를 다시 만든다. 실행 중인 빌드와 잠금 소유자를 먼저 확인한다.
